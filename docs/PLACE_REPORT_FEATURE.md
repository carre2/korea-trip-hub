# 장소 레포트 생성기 — 기획/설계 문서 (SSOT)

_작성 2026-11-08 · 프로젝트 ktriphub.com · 상태: Phase 0(스파이크+프로토타입) 완료, Phase 1(MVP) 착수 대기_

> 이 문서는 "장소 레포트 생성기" 기능의 **단일 기준 문서(SSOT)**다. 결정·검증 결과·설계·로드맵을 모두 여기에 모은다. 실제 데이터 검증을 거친 사실만 담는다.

---

## 0. 한 줄 정의

사용자가 **장소·도시·지역·축제·시장**을 입력하면 → 한국관광공사 TourAPI 실데이터로 **기관 보고서형 여행 리포트**(지도·가는법·볼거리·먹거리·투어·숙박·실용정보)를 자동 생성하고 → **구독 동의 후 사용자가 선택한 채널**(이메일/카톡/SNS/PDF)로 보내주는 기능.

전략적 의미: "비자 보고 짧게 보고 이탈"하던 트래픽을 **깊은 탐색 + 제휴 수익 + 리드 확보**로 전환하는 **플래그십 도구**. 기존 로드맵 ⑥인터랙티브맵 + ⑦지역뎁스 + ⑧Quick Trip Blueprint를 흡수한다.

## 1. 확정 결정 (사용자 승인, 2026-11-08)

1. **사실 정확도** — 공공데이터를 쓰되 100% 재확인되지 않은 데이터(~20~30%)도 사용한다.
   - ❌ **날조 금지**(출처 없는 주소·가격·상호 창작) = 타협 불가
   - ✅ **출처 있는 미재확인 데이터는 적극 사용** + `신뢰도 배지` + `출처 링크` + `공식 확인 권장`
   - → 이 방식이 곧 "기관 보고서"의 신뢰성이다(기관 리포트는 원래 출처·기준일을 표기).
2. **발송** — 자동 발행이 아니라 **구독자 동의 → 본인이 채널(이메일/카톡/SNS) 선택 → 발송**. 공개 피드 자동게시는 하지 않는다.
3. **레포트 형식** — 나열식 금지, **진짜 기관 보고서형**(표지·목차·섹션 번호·출처 섹션) + 관련 정보에 **URL 링크로 리포트 내부 이동**.
4. **서버** — 필요 시 **유료 플랜으로 확장**(KV 캐시·외부 API·메일 발송 넉넉히 설계).

## 2. 데이터 엔진 — 한국관광공사 TourAPI (검증 완료)

### 2.1 계정/키
- 발급처: 공공데이터포털(data.go.kr). 사용자 계정에 **4개 서비스 승인**:
  - `한국관광공사_국문 관광정보 서비스_GW` → **KorService2** (한국어)
  - `한국관광공사_영문 관광정보 서비스_GW` → **EngService2** (영어)
  - `한국관광공사_두루누비 정보 서비스` (걷기·자전거길, 보너스)
  - `한국관광공사_고캠핑 정보 조회서비스` (캠핑장, 보너스)
- **인증키 = 계정 공통 Decoding 키 1개**(승인된 모든 서비스에 적용).
- ★**키는 Cloudflare Worker 시크릿에 저장**한다. 레포지토리/프런트엔드에 절대 노출 금지.

### 2.2 엔드포인트 (검증됨)
- Base: `https://apis.data.go.kr/B551011/{KorService2|EngService2}/`
- 오퍼레이션:
  - `searchKeyword2` — 키워드 검색(substring 매칭)
  - `areaBasedList2` — 지역 기반 목록(areaCode / sigunguCode)
  - `areaCode2` — 지역/시군구 코드 조회(드릴다운용)
  - `locationBasedList2` — **좌표 반경 검색**(mapX, mapY, radius, `dist` 반환) ← 핵심 엔진
  - `detailCommon2` — 상세 공통(overview 등) ※ KorService2는 `defaultYN/overviewYN` 등 **파라미터 받지 않음**, `contentId`만
  - (미사용) `detailIntro2`(영업시간 등), `detailImage2`(추가 이미지)
- 공통 파라미터: `serviceKey`(Decoding 키), `MobileOS=ETC`, `MobileApp=ktriphub`, `_type=json`, `numOfRows`, `pageNo`
- 응답 주요 필드: `title`, `addr1`, `mapx`, `mapy`, `firstimage`, `tel`, `contenttypeid`, `lclsSystm1/2/3`, `dist`, `contentid`, `modifiedtime`
- **사진**: `firstimage`는 `tong.visitkorea.or.kr`(KTO 공식) → **photo-policy 충족**. `http→https` 승급 필요. 저작권은 `cpyrhtDivCd`(Type1 출처표시 등) 준수.

### 2.3 ★분류는 contentTypeId가 아니라 `lclsSystm1`
- **contentTypeId 체계가 서비스별로 다름**: 국문 `12~39`(관광지12·문화14·축제15·숙박32·쇼핑38·음식39) vs 영문 `76~85`(신분류). → contentTypeId로 필터하면 **영문에서 0건**.
- 해결: **`lclsSystm1` 대분류코드로 분류**(모든 언어 동일). locationBasedList2/areaBasedList2를 **필터 없이 1콜**(numOfRows=100) 받아 클라이언트에서 버킷팅 → 12로케일 단일 코드.

| lclsSystm1 | 의미 | 리포트 섹션 |
|---|---|---|
| `FD` | 음식 | 먹거리 |
| `AC` | 숙박 | 숙박 |
| `SH` | 쇼핑 | 쇼핑 |
| `VE` | 문화시설·박물관 | 볼거리 |
| `HS` | 역사 | 볼거리 |
| `NA` | 자연 | 볼거리 |
| `EV` | 행사·공연 | 볼거리(행사) |
| `EX` | 체험·의료관광(병원 등) | **기본 제외** |
| `LS` | 레저·스포츠 | (옵션) 액티비티 |

- 볼거리 = `VE + HS + NA + EV`, 먹거리 = `FD`, 쇼핑 = `SH`, 숙박 = `AC`. `EX`는 의료관광 클리닉이 섞여 기본 제외.

### 2.4 검증된 함정 / 학습
- **한글 키워드**는 `encodeURIComponent` 필수(Worker 자동, 로컬 셸은 pre-encode 필요).
- `searchKeyword2` 결과의 `areacode`가 **빈 값인 경우가 많음** → areaCode 필터 말고 **좌표 근접 매칭**으로 장소 해소.
- 랜드마크에 사진이 없을 수 있음 → **주변 POI 사진 폴백**.
- `areaCode2`(제주)에 **레거시 '남제주군/북제주군'**이 섞임 → 현행(제주시·서귀포시) 우선 필터.
- `areaBasedList2 arrange='O'`는 대표이미지 있는 제목순 → 일부 분류가 빈칸일 수 있음(페이지네이션/랭킹 튜닝 포인트).

## 3. 입력 리졸버 — 3가지 데이터 모드 (검증 완료)

사용자가 무엇을 입력하든 자동으로 알맞은 모드로 분기한다.

| 모드 | 입력 예 | 데이터 소스 | 비고 |
|---|---|---|---|
| **radius** (점) | 명동, 홍대, 성수 | `locationBasedList2(좌표, 반경)` | ★반경 **밀도 적응** 필요: 도심 ~1.3km / 농촌 ~15km |
| **area** (광역) | 제주도, 충청남도 | `areaBasedList2(areaCode[, sigunguCode])` + `areaCode2` **시군구 드릴다운 칩** | 광역 → 하위로 좁히기 |
| **resolve** (해소) | 예산시장, 특정 상호 | `searchKeyword2`로 좌표 찾고 → radius 검색 | 좌표 미상 지점 |

- **입력 정규화/중의성 해소**: 다국어·로마자·한자·오타 → `searchKeyword2` + 지오코딩 폴백. 매칭이 복수면(예: "강남 지역" vs "강남역", 여러 "시장") **선택 UI**로 되묻는다. (상세 UX는 Phase 1 설계)
- 지역 코드 참고: 서울=1, 충남=34, 제주=39.

## 4. 다국어 (12 로케일)

- TourAPI 언어 서비스: 국·영·일·중(간/번)·독·불·스·러.
- 우리 12로케일 중 **네이티브 데이터(8)**: `ko, en, ja, zh(간), zh-TW(번), fr, es, ru`.
- **TourAPI 미지원(4)**: `vi, th, id, ms`(베트남·태국·인니·말레이) → **영문 데이터 + 번역 레이어**(`i18n-translate-verify` 스킬) 또는 영문 폴백. (정책 미확정 — §10)
- **UI 문자열**(섹션 제목·배지·버튼 등)은 12로케일 i18n 전체 번역.

## 5. 리포트 포맷 (기관 보고서형)

```
[표지]  장소명(현지어+로마자) · 대표 실사진 · 생성일 · 1줄 요약 · 신뢰도 범례
[목차]  앵커 링크(클릭→섹션 점프) · 데스크톱 좌측 고정 목차(스크롤 시 현재 섹션 하이라이트)
───────────────────────────────
1. 개요          (개요 텍스트 detailCommon2 + 주변 집계 + 광역이면 드릴다운 칩)
2. 위치 & 지도    (Leaflet + OSM · 실좌표 마커 · 색상별 분류 · 마커 클릭→상세)
3. 가는 법        (교통수단별 · facts.json 연동 예정 · 변동값 ⚠ 공식확인)
4. 볼거리         (VE·HS·NA·EV · 가까운순 · KTO 실사진)
5. 먹거리 · 쇼핑   (FD / SH · 가격·영업시간 ⚠ 공식확인)  ※ 한국인용: 특산품·먹방(유튜브 큐레이션)
6. 투어 · 액티비티 (Klook 제휴)
7. 숙박 ★         (AC TourAPI 숙소 + Stay22 지도 임베드 — 수익 핵심)
8. 실용정보        (환전·교통패스 + 블로거 여행기 링크아웃)   ※ 현재 프로토타입은 3·8 일부 통합
9. 출처 & 기준일   (모든 데이터의 출처·수집일 · 신뢰도 정책)
───────────────────────────────
[CTA]  이메일로 받기 · 카톡 공유 · SNS 공유 · PDF · My Trip 저장
```

- **내부 내비게이션**: 목차 앵커 + 지도 마커→섹션 점프 + 상호참조 칩(→가는 법, →숙박 등).
- **신뢰도 배지**: `✓ 검증`(공식·최신) / `⚠ 참고`(출처 있음·변동가능 → `공식 확인` 안내). 각 항목에 `[출처]` 링크.
- 모든 섹션 구조는 **12개 언어로 자동 현지화**.

## 6. 신뢰도 · 콘텐츠 정책 (전역 제약 준수)

- **facts-harness**: 출처 없는 수치/주소/상호 생성 금지. 변동값(가격·시간·공실)은 **출처 + 기준일 + "공식 확인"** 표기. 미검증은 `⚠ 참고` 배지.
- **콘텐츠 = 하이브리드**: 사실(이름·주소·좌표·분류)은 **API 그대로**, 내러티브(요약·동선)는 **AI가 전달받은 사실 범위 내에서만** 생성(수치 창작 금지).
- **photo-policy**: KTO 공식 사진(tong.visitkorea)만. 실존 명소 AI 위조 금지.
- **가짜 후기 금지**: 먹방·여행기는 **실제 영상 큐레이션**(oEmbed 검증) / **블로그 링크아웃**(본문 미복제·저작권).

## 7. 제휴 (수익)

- **Klook** (투어·액티비티·패스) — 기존 제휴(aid 130139) 재사용.

  - ⬜ Stay22 **임베드/제휴 ID** 사용자 계정에서 확보 필요.
- (옵션) eSIM 등 — Klook 내 재사용.

## 8. 발송 정책

- 원칙: **자동 발행 금지**. 구독 동의 → 사용자가 채널 직접 선택 → 발송.
- 채널:
  - **온라인 리포트**(공유 가능 URL) · **PDF 다운로드**(클라이언트 생성) · **Web Share**(OS 공유시트)
  - **카카오톡**: Kakao JS SDK 공유(사용자가 수신자 선택)
  - **이메일**: 동의 체크 + Worker 발송 + **개인정보처리방침 갱신** 필요
- [[sns-auto-post-ban]] 교훈: 공개 피드 자동 업로드는 절대 안 함.

## 9. 아키텍처

- **프런트**: Next.js 정적 export(현 구조 유지) = UI 셸·리포트 렌더. 지도 = Leaflet + OSM(키리스).
- **서버 로직 = Cloudflare Worker**(`worker/index.js` 확장):
  - `POST /api/place/resolve` — 입력 정규화·중의성 해소·모드 판정(좌표/지역/해소)
  - `GET  /api/place/report` — TourAPI 조합 → 리포트 JSON(캐시)
  - `POST /api/place/send` — 이메일 발송(동의 검증)
- **캐시 = Workers KV**: `place+lang` → 리포트 JSON. TTL = 정적 데이터 7~30일, 변동(가격 등) 짧게. TourAPI 개발계정 한도(일 1,000건) 대비 캐시 필수.
- **LLM** = 기존 `/api/chat`(Claude) — 내러티브 요약·동선만, 사실 범위 내.
- **배포 게이트**: 데이터/코드 변경 시 prebuild 7게이트 통과 후 push([[ktriphub-deploy-gate]] — 무음 차단 주의).
- **키 관리**: TourAPI 키, (추후) 메일·Stay22 키는 Worker 시크릿.

## 11. 열린 결정 (사용자 입력 필요)

1. **MVP 발송 범위** — 온라인+공유+PDF 먼저(이메일은 Phase 2) vs 처음부터 이메일 포함
2. **Stay22 제휴 ID** — 사용자 계정에서 확보
